# ULike v1.9.82 — GPU 診断の詳細化

公開済み ULike v1.9.81 / Hiro Morphe Patches v1.0.214 を基準に、採用した CPU/GPU 処理、経路と終了理由、作業累計、GPU 枠受付ロックの取得待ち、認定の状態を記録します。新規配布は ULike v1.9.82 / 総合版 v1.0.215 です。画質の計算、解像度、処理経路、保存設定、既存の認定キーは保持します。

## 診断する内容

Strong の画質認定と速度条件を区別し、GPU の利用枠が取れなかった理由を記録します。画像を GPU に保持する経路では、成功、CPU への退避、中断、失敗を終了時点の状態として残します。

CPU/GPU の件数は実際に結果を採用した処理を数えます。GPU の失敗試行やバックグラウンドの画質照合を、その写真で採用した GPU 処理へ加算しません。未計測の作業時間は未計測と表示します。Strong の既存作業累計を保持し、GPU 枠内の待機・判定作業と GPU 枠受付ロックの取得待ちを分けます。Strong の累計には並行ワーカーや採用されなかった候補の時間を含む場合があり、工程の経過時間とは一致しません。全工程の失敗試行を新たに独立計測する変更ではありません。

認定の表示は、検証の予約・実行中、直近照会キャッシュの確認済み記録・画質不一致の拒否、画質不一致以外の履歴における再試行の時間条件・間隔待ち・上限を区別します。表示だけで判定や永続化を変更しません。確定した写真の記録は後の状態変化から分離します。

## 保持する処理

NR、美肌、シャープ、肌・輪郭・暗部の保護、色空間、ビット深度、HDR / gainmap、HEIF 設定と単写条件を保持します。.81 の保存準備、メモリ制限、所有権、CPU 退避、キャンセル、独立した 2 回の全出力一致と速度条件も保持します。

全 12 native ペイロード、GPU program 0〜50、native 登録、JNI は .81 とバイト単位で同一です。新しい native バイナリや JNI は追加しません。既適用の SaveRuntimeHooks1981 は再実行せず、保存・顔解析・プレビューの対象クラスを .81 から保持します。再コンパイルする ProcessingTiming に既存の TimingCameraHooks を一度適用し、元の 2 個のカメラ監視呼び出しを保全します。
