# ULike v1.9.80 — 全体監査・失敗時の復旧・未使用経路の整理

基準は公開済みULike v1.9.79 / Hiro Morphe Patches v1.0.212です。GitHub mainの不変コミット `307f90a9d3062c32ab65930fb1c0f04d22a91d9d` と実配布MPPのSHA-256を照合して作業しています。新規配布はULike v1.9.80 / 総合版 v1.0.213です。

## 発見した問題と修正

GPU各経路で、画像出力を受け取れなかった失敗まで恒久的な画質不一致にしていました。実際の出力を比較する前のnull、実行例外、クラス解決失敗は、既存の待機時間と回数制限を伴う再試行へ分けます。真の画質不一致は拒否を維持し、キャンセル・GPU使用中・メモリ不足を成功として認定しません。旧版の不一致記録を一括削除する処理は追加しません。

インカメラでは、最後の再開試行が受理された直後や締切直前に、フレーム監視も打ち切っていました。再起動の上限と元の締切を維持し、受理済みの映像到着を期限まで待ちます。再startを行わない待機区間ではネイティブ状態を繰り返し取得せず、期限時に現所有者を確認してから診断記録を残します。

保存では、予約後のLinkageError等と、失敗診断自体の追加エラーによって画像・保存枠・終了待ちが残る経路を修正します。保存ジョブへの受け渡し前後で所有権を分け、後始末は診断の成否から独立させます。既知の省略可能な処理失敗は安全に終端し、それ以外の致命的Errorは後始末の後に再送出します。

旧実行エンジンWholeRoute1952の現用依存はWorkインターフェースのみでした。現用の1953実行経路とWork契約を維持し、到達しない旧エンジンを削除します。StrongNoise1958の未使用private prepareScaleと常時falseの旧GPU分岐、読み手のいないGate/State値も整理します。旧ソースは監査用の固定参照として保管し、現行ビルドへの混入を検査します。

解像度、ノイズ除去の強さ、肌・輪郭・暗部の保護、シャープネス、保存形式と圧縮設定は変更しません。ノイズモデル整理は旧版と同じ入力を別プロセスへ与えて、出力・モデル係数を比較します。全12nativeペイロード、GPU program 0〜50、nativeインストーラー、JNIは.79実配布物からバイト単位で同一のまま継承します。取得済み認定の環境識別子を変更しません。

処理変更を認めるJavaルートは `src/production1980.json` に固定します。その他の現用クラス、元アプリの差し替えメソッド、単写条件、カメラと診断のフック、総合版の他アプリ資源は、ビルド時に実DEXとZIPで検査します。削除対象への残存メソッド・フィールド参照は全体から検査します。
