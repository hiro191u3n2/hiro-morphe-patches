# OneBack v1.1.24 — Instagramの外部プロフィールと子画面のBack判定

Instagram 452.1.0.53.64で、外部プロフィールURLの認識漏れと、別プロフィールの戻る結果を消費してしまう判定の2箇所を修正します。総合パッチはv1.0.311、基準は公開済みv1.0.310です。基準版に含まれるTikTok Link Direct v1.0.2を含め、非対象パッチのローダー・拡張・メタデータ・資産の保持を検証します。

## 修正した2つの問題

### 外部URLから作られたプロフィールの認識漏れ

原本InstagramのURL処理は、通常のWebプロフィールURLに加え、`https://www.instagram.com/_u/NAME/`と`instagram://user?username=NAME`からもプロフィールを作成します。後者2つの経路では、解析結果にParcelable型の`uri`が付かず、外部URL用の処理が保持する`original_url`に元のURLが残ります。v1.1.23は`uri`を必須としていたため、これらのネイティブ経路で作られた最初のプロフィールを終了対象として登録できませんでした。

v1.1.24は、原本で確認した外部URL用の引き継ぎ情報を照合して認識します。対象は次の3形式に限定します。`NAME`は、Instagramが解析して渡したユーザー名と一致する必要があります。

| URL形式 | `uri`の条件 |
| --- | --- |
| `http(s)://www.instagram.com/NAME/` | Parcelable型のUriが必須で、`original_url`と一致すること |
| `http(s)://www.instagram.com/_u/NAME/` | 省略を許容。存在する場合はParcelable型のUriで、`original_url`と一致すること |
| `instagram://user?username=NAME` | 省略を許容。存在する場合はParcelable型のUriで、`original_url`と一致すること |

Web形式では`instagram.com`と`m.instagram.com`も認識し、末尾のスラッシュは省略できます。URLだけで終了対象にはしません。`original_url`、Boolean型の`true`である`IS_ON_CREATE`、Main / URL / Launcherの各Activityに対応する解析元情報、ユーザー名の一致を要求します。アプリ内のURL解析結果だけを持つ経路や、内部リンクのフラグが立った経路は対象外です。未確認のクエリ、QR用指定、リール・作成シートなどを直接開く制御も拒否します。

この照合は、確認したURL用の処理を通る経路と、アプリ内の解析結果だけの経路を区別するためのものです。起点がブラウザだったことの証明ではありません。アプリ内部からの自己Intentが同じURL用処理へ入り直す場合もあるため、全ての内部起動を区別できるとは扱いません。明示的な内部リンクフラグは引き続き拒否します。

### アプリ内で開いた別プロフィールの戻りを保持

外部リンクから登録された最初のプロフィールとは別のプロフィールをアプリ内で開いた場合、共通の`UserDetailFragment`向け終了判定が、本来のBack処理の`false`を消費済みとして扱う経路がありました。

v1.1.24は、判定を受けるFragmentが登録済みの最初のプロフィールそのものであることを確認します。別プロフィールのネイティブ結果はそのまま呼び出し元へ返し、アプリ本来の子画面からの戻りを妨げません。元のプロフィールが同じBack操作中に再表示されても、その操作で終了させない保護は維持します。

## 動作の範囲と実機での再確認

- 終了を許可するのは、確認した外部経路から登録された最初のプロフィールで、画面・階層・入力状態のガードを満たし、Instagram本来のBack処理が操作を消費しなかった場合です。
- そのプロフィールから開いた投稿・リール・別プロフィールは、先にInstagram本来の処理で戻ります。最初のプロフィールが再表示された同じBack操作では終了しません。
- コメント欄、キーボード、ダイアログなどを閉じる処理と、ネイティブが既に消費したBack結果を優先します。
- 呼び出し元ブラウザのタスクを削除せず、Instagram内で通常開いたプロフィールを一律に終了対象にはしません。

自分自身のプロフィールを開く別の生成経路、確認できない再生成後の識別情報、二画面や別のFragmentManagerへ経路を切り替える設定などは、確認済みの終了対象に含めません。

今回の修正は原本コードとホストモデルで確認した2つの不具合に基づきます。利用者の端末でブラウザから実際にどのURI・起動Intentが渡されたかは取得していません。報告された「最初のプロフィールで戻っても終了しない」症状が、この修正で解消するかは実際の端末で再確認が必要です。Android 17 / Samsung SM-S948Qでの画面操作・動作確認は行っていません。

## 適用

Morphe Managerの既存ソースを更新し、**パッチ適用前のInstagram 452.1.0.53.64**に「戻る1回で終了・履歴削除」を適用して、生成APKをインストールします。ソースの更新だけではインストール済みアプリ内のパッチは更新されません。このInstagram452用修正は、OneBack適用済みAPKへの上書きには対応しません。古いOneBackの版にかかわらず、OneBackを適用していない原本から作り直します。

適用後は、ブラウザから対象プロフィールを開いて戻る操作を確認し、そこから投稿・リール・別プロフィールへ進んだ場合には、先に元のプロフィールへ戻ることも確認します。キーボードやダイアログがある場合は、それらを閉じる処理が優先されることを確認します。

再確認用に、`HiroBack131`タグの診断ログを追加しています。登録時はURL形式の番号とActivityに対応するモジュール名、終了処理へ進む時はその印だけを記録し、URL本文やユーザー名は含めません。このログは処理を通った箇所を示すもので、端末上の終了成功そのものを証明するものではありません。

Pikoなど別のパッチソースを同時に選択する組み合わせは、この検証では再現していません。総合v1.0.310の非対象ローダー、拡張、リソース、通知文と既存のアップグレード参照は変更対象に含めません。

## 公開に必要な検証

`src/build.py`は実Android SDKでコンパイルし、必須のInstagram/X/TikTok/Trip.comホスト回帰、外部URLの引き継ぎとプロフィール識別の回帰、ネイティブBackラッパー、DEX保存と実Morpheローダーのメタデータを検査します。今回の必須回帰は`Back131InstagramProfileRouteTest`と`Back131InstagramProfileIdentityTest`です。基準のOneBackランタイムは93クラスで、実装変更を認めるのは`InstagramExternalProfile`だけです。その他は命令・例外処理・注釈・フィールド等を照合し、デバッグ情報以外が一致するクラスを基準版の完全な定義に戻します。

公開処理は、最終の単体・総合MPPの両方を原本Instagram APKへ適用した実記録と、生成APKのネイティブ処理保存・プロフィールフック監査を要求します。原本は143,237,227バイト、SHA-256 `22f20062d16997e26009e73b0425974efef8ac69c76dd8912ee8a091213c39e2`です。2回のローカルビルドと2回のCIビルドで、MPPとQAのバイトが一致する必要があります。

変更対象外のZIP資産とネイティブライブラリはバイト単位で照合します。`resources.arsc`は原本のリソースID・型・設定・値と文字列/スタイル情報を検査し、同じSDKで基準v1.0.310を適用した出力との意味上の一致を要求します。既存SDKによる一部のエントリ名正規化も、基準版と一致することを要求します。

原本の外部URL引き継ぎ・プロフィールタブ・モーダル経路の静的契約は`PROFILE_TAB_CONTRACT.md`にあります。静的観察とホストテストを実機操作の代用にはせず、実行結果を最終のQAファイルに記録します。過去版の証拠や合成した成功値では代用しません。原本APK、生成APK、Instagramのネイティブメソッド全文は公開資産に含めません。

ビルドと公開の手順は`publication/BUILD_LOCAL.md`にあります。
