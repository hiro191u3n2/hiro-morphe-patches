# Hiro TikTok 47.5.3 v4.0.0

これまでの Hiro 製 TikTok パッチを、グローバル版 `com.zhiliaoapp.musically` の **47.5.3** に合わせて実装し直した版です。対応バージョン欄の追加だけではありません。元の APK にあるメソッド、表示条件、ビューの初期化、ネイティブライブラリを調べ、出力 APK に実際の修正が入ることを検証します。

## 配布ファイル

- `TikTok_47.5.3_Hiro_v4.0.0.mpp`：今回の TikTok 向け8項目をまとめた追加パッチ。
- `Hiro_Morphe_Patches_v1.0.280.mpp`：既存の Hiro 統合版を更新したファイル。TikTok 以外のパッチも含みます。

同じパッチが重複するため、通常はどちらか一方を読み込んでください。日本語設定を使う場合は、別途 [icysymmetra の TikTok パッチ](https://github.com/icysymmetra/tiktok-patches-for-morphe/releases/tag/v0.9.0-dev.1) の `Settings` が必要です。

## 修正内容

| 左下の文字・再投稿欄 | 実際の `left_container` に接続し、ビューの再利用や再表示後も非表示を維持。元の初期化処理を保持。 |
| CapCut・エフェクト・場所等の誘導枠 | 旧形式と新しいアンカー生成処理、下部ボタン、再投稿表示の経路を対象化。 |
| シークバー常時表示 | 表示・ドラッグ・逆向き実験の判定を更新。表示状態のキャッシュが同じ値だと描画を飛ばす問題も修正。LIVE、画像投稿など元の除外条件を保持。 |
| シーク中のプレビュー | 実際のプレビュー読み込みと表示で共有される条件に接続。動画側にプレビュー画像があるかどうかの確認は保持。 |

ネイティブ機能6項目はパッチ名の末尾に `（TikTok 47.5.3）` が付きます。OneBack は既存の名前で、内部実装を **1.1.20** に更新します。日本語化は必要な場合に選択する項目です。

## 適用方法

1. Morphe Manager **2.1.0-dev.2** の **「設定」→「パッチ処理」→「エキスパート モード」** をオンにし、確認画面で **「有効化」** を押します。
2. 上記の MPP を一方だけ読み込みます。日本語設定を使う場合は、Metra `0.9.0-dev.1` のソースも有効にします。
3. パッチ未適用の **TikTok 47.5.3 / `com.zhiliaoapp.musically`** の完全な APK を選びます。今回検証した versionCode は `2024705030` です。
4. パッチ選択画面の Hiro ソースで必要な項目を選びます。日本語設定を使う場合は、Metra 側の **`Settings` を手動で有効化**し、Hiro 側の **`TikTok設定を日本語化`** も同時に選びます。日本語化は既定では未選択です。端末またはアプリの言語を日本語にします。
5. 選択内容を確認して適用し、選択した全項目が成功したことを確認します。失敗したパッチを無視して出力した APK は使わないでください。

未選択の `Settings` が見つからない場合は、検索条件を消し、一覧上部の**選択件数／フィルターのバッジ**をタップして「選択されたパッチのみを表示」を解除します。新しいネイティブ機能6項目と OneBack は、上流 Settings がなくても適用できます。Manager の選択経路と日本語の画面名は、指定版のソースで確認しています（`src/validation/manager/manager-selection-audit.md`）。

47.5.3 の `com.ss.android.ugc.trill` や、別の TikTok バージョンには今回のネイティブ機能を対応済みとして表示しません。元の APK の構造が確認したものと異なる場合は、該当機能が具体的な理由を出して停止します。

## 上流パッチとの関係

今回更新する対象は **Hiro 製の8項目** です。icysymmetra の `0.9.0-dev.1` 全136項目を 47.5.3 に試した調査では、124項目が適用され、次の12項目は失敗しました。この調査結果を成功した配布物として扱いません。

- AMOLED dark theme
- Block P2P video relay
- Comment tools
- Feed text sizes
- Hide Play Store update offer
- Hide inbox items
- Hide search suggestions
- Lift text length limits
- Mute feed videos
- Remove LIVE extras
- Remove unused language packs
- Show follow status

これら12項目を修正したという意味での上流全体の 47.5.3 対応は主張しません。上流の設定画面と日本語化については、今回の全 Hiro 機能との併用を別途検証します。

## 検証と公開条件

入力は署名検証に成功した元のグローバル版 APK です。

- APK SHA-256：`6670ca3f93bfea379658cad3c27f05d3a380b23a0d82569cce684b7453e8ff3e`
- 署名証明書 SHA-256：`9041803e91bcb814b4b4399fb5c85a91640b755e5e8ba76813814bf4cf2ab5ba`
- 元のクラス数：480,524

公開には次の2ケースの完全な適用と再構築が必要です。

1. TikTok単独 MPP：ネイティブ6項目＋OneBack。
2. Hiro統合 MPP：上記7項目＋日本語化＋上流 `Settings`。

どちらも選択した項目と成功した項目が一致し、失敗が0件で、すべての処理段階が成功している必要があります。成功と出ただけでは公開せず、出力 APK のネイティブ呼び出し、分岐の動作、クラス・メンバーの保持、通信保護の変更、設定の日本語化経路を検査します。

ローカル2回と GitHub Actions 2回の独立したビルドで、MPP とビルド検証レポートが完全一致することを必須にしています。さらに実 APK の検証に使った MPP と一致しない成果物は公開できません。

**Android 実機での画面操作、サービス接続中の挙動、SM-S948Q / Android 17 での操作確認は行っていません。** サムネイルは TikTok がその動画に画像データを提供している場合に表示できます。通信保護は明示した既知の追跡先に対する処理で、あらゆる通信の動的な分類や遮断を保証するものではありません。

詳細な証拠は `src/validation/real-apk.json`、`src/validation/real-apk/`、`src/validation/metra/` とリリース添付の QA JSON に保存します。元の APK やパッチ後の APK はリリースに含めません。

## ソース・再現

ビルドと検証の手順は `publication/BUILD_LOCAL.md` を参照してください。`src/build.py` は固定したツールと統合版1.0.279を入力にして2種類の MPP を生成します。`src/validate_apk.py` は元の APK をローカルで検証・適用し、公開に必要な証拠を作ります。

OneBack の `TikTokHome` 以外の実行クラス84個、日本語化のローダーと実行ファイル、統合版の対象外資源を保持したこともビルド時に検査します。日本語化の元ソースは `efb5937ddea4fe29abdfe33027cfc0e5d397ae93` の `releases/tiktok-japanese100` で、配布するソースZIPにも含まれます。
