# Berry Browser BFCache復帰補正 v1.4.2

Hiro Morphe Patches v1.0.334に収録するBerry Browser用パッチです。
戻る操作を繰り返すと表示が崩れる症状に対し、同じ文書のURL変更への追従と、対応WebViewのネイティブ復帰判定を追加します。
**実機で表示崩れの解消を確認した版ではありません。**

## 修正内容

前版は、復帰開始時のURLと現在のURLが一致しないと補正を進められませんでした。
`history.replaceState()`などで同じ文書のURLだけ変わった場合も補正が止まることをホスト試験で再現しました。
この版では文書の識別情報と移動の世代を照合し、同じ文書のURL変更を扱います。単にURLの条件を取り除く変更ではありません。

対応するWebViewでは、ブラウザー本体が通知するページ識別情報によってBFCache復帰を確認する経路も追加します。
復帰を通常の新規文書読み込みと区別し、JavaScriptの通知だけに依存しないようにします。
必要な機能がない環境では、既存のページ復帰通知を使う経路を維持します。

復帰が確認できた場合に限り、新規読み込み用の状態切替と開始時の優先度切替を抑えます。
URL・タイトルの準備、表示中タブ、サイト別設定など、ページ開始処理の残りは維持します。
その処理が終わった後に、現在のページのURL・タイトルと読み込み完了状態を同期します。古いページや所有者が違うタブには適用しません。
構造を一意に証明できない読み込み状態の箇所はそのままにし、開始処理の引数が途中で書き換わる未知の構造は適用前に拒否します。

ネイティブのページ識別記録は最大64件で、ページ削除通知と上限超過で破棄します。これは判定用の記録数であり、BFCacheの保持ページ数設定は変更しません。
既存のPage識別情報を上書きせず、対応APIや安全な識別情報が得られなければ従来のJavaScript経路を残します。診断ボタンは追加しません。

## 今回までの実機報告と限界

- BFCacheをOFFにすると正常。
- 保持ページ数を10から1へ減らしても改善しない。
- ユーザースクリプトを全部OFFにしても再現する。
- 崩れた後に再読み込みすると正常に戻る。
- 前版1.4.1／統合版1.0.332でも改善していない。

同文書のURL変更による対象漏れは再現したコード上の不具合ですが、今回の実機症状の原因だったとは未証明です。
メモリ不足、描画プロセス終了、GPU停止とも断定していません。

## 適用

1. Morphe ManagerでHiro Morphe Patchesを1.0.334へ更新します。Berry専用ソースを使う場合は1.4.2へ更新します。
2. 未改造のBerry Browserを入力に、次の5パッチを選びます。
   - ダブルタップから指を離さず片手ズーム
   - プレビュー作成を後回しにして表示中タブを優先
   - ロックフリーMessageQueueを有効化
   - 共有先ブラウザの表示を個別に切替
   - バックフォワードキャッシュの復帰処理を補正
3. 統合版とBerry専用版は重複選択しません。以前と同じ署名キーで更新インストールします。
4. BFCacheとオートページャーは普段の設定のまま、新しいタブから問題が起きていた往復を確認します。

ソースの更新だけではインストール済みのアプリに変更は反映されません。
アンインストールやデータ消去は不要です。

## 維持する動作

BFCacheの有効設定・最大ページ数、オートページャー、既存4改造を維持します。
強制リロード、履歴やキャッシュの削除、スクロールや倍率の変更、ユーザースクリプト全体の再実行は追加しません。
全バージョン表示と構造自動検出を引き継ぎ、必要な構造を確認できる入力だけに適用します。
統合版は最新1.0.333をベースにし、ULike v1.9.123を含む他アプリの定義と資産を保持します。

## 検証とソース

`payload/QA_apply334.json` は配布MPPのハッシュと適用試験、リリースの `QA_build334.json` は構築と保持検証、`payload/RUNTIME_BUILD_QA.json` は復帰判定の試験を記録します。
復帰調整41ケース／73検証、JavaScript19検証、ネイティブ判定5ケース／40検証、連携13ケース／29検証を実行します。
ネイティブ完了処理のメタデータ保護9件・既存4件、開始時引数の保護6件の拒否試験を `qa/native_audit/` に保存します。
保存済み未改造3.83.74と、クラス・メンバー名を変更した検証入力を使用します。
実際のBerry 3.84.12のAPK、Android実機の表示・通信・症状解消は未検証です。
ホスト上の通知シミュレーションと、実機のWebView・描画動作を区別します。

`src/` はパッチ定義、`runtime/` は復帰補正本体と試験、`build/` はMPP構築・保持検証、`qa/` は適用検証、`audits/` は開始処理・ページ識別情報の監査記録、`publication/` は公開処理です。
元APK、署名キー、閲覧データは公開しません。
固定した統合版1.0.333をベースにランタイムとMPPを2回構築し、同じバイト列になることと検証済みハッシュを確認します。
既存Siteへ公開した後、GitHubリリースとManagerのmain/dev更新情報を反映します。他アプリの内容・履歴を保持します。
