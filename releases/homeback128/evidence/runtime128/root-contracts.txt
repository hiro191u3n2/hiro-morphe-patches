Instagram root-Reels contract review for OneBack 1.1.18

Scope
- Static verification of the supplied Instagram 452.1.0.53.64 merged original APK.
- Fresh production-SDK compilation of the new helper and integrated runtime.
- This report contains authored findings, public signatures and hashes, not APK
  contents, account data, media, credentials or disassembly instructions.
- Physical Android screen navigation has not been executed by this review.

Observed weakness in the previous runtime
- Its exact Reels boundary could exit any Reels receiver when the profile-source
  exception did not positively identify that receiver.
- Its tab boundary could exit an unchanged CLIPS controller root without proving
  that the selected leaf was root Reels or that its parent stack was empty.
- The generic visual fallback did not require InstagramMainActivity. A separate
  video-host Activity must retain native finish so that the existing profile
  Activity underneath becomes visible, rather than removing the whole task.
- These are code-level paths. The exact path taken on the user's device is not
  asserted from a static audit, and no claim is made that the PROFILE enum was
  lost or changed on that device.

Verified native 452 structure
- InstagramMainActivity.A1f delegates through its navigation object to the
  controller's A05 current root. A06 supplies the selected tab enum.
- The native tab-host return helper selects a MAIN overlay before its base child.
  It offers Back to that child before checking the child FragmentManager's A0L
  count and performing the existing queued or immediate pop.
- Consequently a nested video must decline the custom exit gate so that this
  native parent continuation can reveal its prior screen.

New helper invariants
- Only InstagramMainActivity with verified owning controller and CLIPS tab is
  eligible. A separate ModalActivity is not eligible, regardless of video source.
- Main and controller current-root identities must agree. Non-swipeable roots
  must be the MAIN-container fragment.
- Only the selected wrapper/manager chain is examined. Each fragment must have
  the expected Activity, parent fragment and parent FragmentManager.
- Every examined selected parent/child manager must have A0L()==0. A swipeable
  host's MAIN overlay disqualifies exit even if its count is zero.
- Known BASE, MAIN, merged-page and pager children are followed. Null selection,
  missing manager, wrong owner, cycle, excess depth, unknown shape and failed
  reflection return false. The leaf must be the exact Reels family and, when
  supplied, the exact callback receiver. A null receiver means inspect the
  current selected leaf; it never makes a null selected leaf eligible.
- No retained unrelated tab manager, view/lifecycle heuristic, pending-action
  flag or analytics source is sufficient to authorize exit.

Integration and return-transaction review
- Generic exit, native Reels, Main's early boundary and native tab boundary all
  require the positive root predicate. Existing known profile origins remain
  an additional veto.
- A known nested selection with CLIPS behind it retains the same native Back
  policy through a synchronous pop, including ordinary non-Reels profile/media
  content. Revealing root Reels during that Back does not authorize a second
  exit within the same transaction.
- NATIVE is set at the outer terminal scope and removed on leaving that scope.
  Prediction state is removed at gesture completion/cancellation. Native-return
  tokens are confined to the main-loop dispatch and removed by their own posted
  cleanup token. A later token cannot be removed by an earlier cleanup.
- Native ModalActivity finish is not converted to task removal. Existing
  comment/layer terminal guards remain separate and unchanged.
