# Verified prepared-face model boundaries

This component now runs **both real pinned models** through their respective
normalization, FP32 neural inference, continuous FP64 output mapping and actual
neural-image shader blending. It also implements the verified Natural 106-point
similarity/margin/offset matrix. It is a host component, not an Android patch or
a complete style, face detector, or HDR beauty engine.

| Boundary | Natural blush | Purity2 |
| --- | --- | --- |
| Model input | Prepared 256×256×3 face samples, NCHW at inference | Same tensor dimensions |
| Input scaling | Literal float32 `0.007799999788403511 * code - 1` | Observed no-extra-channel branch: float32 `(code - 127.5) * float32(1/127.5)` |
| Model output | Four 256×256 channels | Four 256×256 channels |
| Continuous post mapping | `(output + 1) / 2` | Same |
| Shader opacity | `min(mask.r, generated.a) * intensity` | `mask.r * generated.a * intensity` |
| Composite | Mix source and generated by opacity; final alpha is 1 | Same |

The Natural coefficient is deliberately **not** changed to 2/255. Native
NH postprocessing defaults to `127.5*x+127.5` followed by byte conversion;
Purity also converts its float output to bytes. This new component replaces that
quantization with continuous values. It does not reproduce the original byte
rounding, accelerated kernel approximation, or GPU rounding.

The verified ONNX FP32 Tanh can undershoot -1 by one float32 ULP. Postprocessing
accepts only ±`nextafter(float32(1), +inf)` and clamps that numerical overshoot to
the mathematical Tanh interval. Larger excursions fail. This is a model-domain
rounding rule, not HDR clipping.

## Explicit input contract

`prepared_channels` is the **post-colour-conversion** face crop in code units
[0,255], including fractional values. The wrapper retains its channel order.
It does not assume that an arbitrary camera RGB, BGR, limited-range YUV, HLG or
linear-light array is equivalent to that boundary. `domain` must explicitly be
`encoded_sdr_full_range`; other domains are rejected. This assertion does not
prove the original model's RGB primaries, transfer function or training domain.

The source RGBA samples, generated samples and external red-channel mask must
already correspond at the shader's respective sampling coordinates. The
wrappers do not generate a mask, select or track a face, establish source image
orientation, perform a crop warp, or apply the later makeup/LUT/geometry passes.
Only the neural image is 256×256; this does not imply the whole saved photograph
is that size. It also cannot prove native 24.5 MP capture.

`run_natural_prepared_face(model_path, bytenn_library_path, prepared_channels,
source_rgba_samples, mask_red_samples, intensity, domain=...)` and
`run_purity_prepared_face(model_path, effect_library_path, bytenn_library_path,
prepared_channels, source_rgba_samples, mask_red_samples, intensity, domain=...)`
load their exact pinned model internally. They reject model substitution rather
than accepting another network with an identical input/output shape. An
unverified external inference session cannot be injected. Returned arrays retain
model input/output, generated samples and the composite for caller validation;
the flags `complete_style`, `hdr_preserved`, `native_pixel_parity` are false.

## Natural alignment math

`extract_natural_template.extract_template(lib_effect)` reads the 106-point
template only from the pinned supplied `libeffect.so`; template coordinates are
not included in this source. `similarity_fit` implements the native algebra in
FP64. `natural_crop_matrix` composes the fitted source→template matrix with
256/(1+2×margin) scaling, margin padding, then pixel offsets. Defaults match the
actual `tt_baoman` metadata: margin=float32(0.4), offset=(0,15).

Callers must supply the correct 106 ordered image landmarks and template. The
native crop-type-1 path can additionally adjust the template based on pose and
`smash_mode`; the function receives the already appropriate template and does
not infer those adjustments. Matrix validation rejects degenerate or nonfinite
inputs. Native FP32 accumulation and interpolation are not byte-matched.

The acquired Purity `face_point` group was independently decoded as a 106-point
template, not a second image inference network. Its 848-byte float payload is
byte-identical to the Natural native template. The strict loader is in sibling
`model_inspect/legacy_face_template.py`. This finding alone does not prove the
Purity crop, pose, affine direction, or sampler is identical to Natural's.

## Reproduce

Requirements are NumPy and the sibling `model_replay` dependencies. With both
module directories on `PYTHONPATH`:

```sh
python -m unittest discover -s beauty_contract -p 'test_*.py' -v
python beauty_contract/verify_real_face.py /private/tt_baoman.model \
  /private/libbytenn.so /private/libeffect.so /tmp/natural_qa.json
python beauty_contract/verify_real_face.py /private/tt_goodlike.model \
  /private/libbytenn.so /private/libeffect.so /tmp/purity_qa.json --style purity2
```

The real-model check uses synthetic fractional prepared samples, preserves
32,768 zero-mask samples exactly, checks independent selected shader results,
retains non-byte output levels, and separately checks the Natural matrix using
the actual extracted template. It is not a photograph, a visual likeness score,
or a comparison with a running phone. No weights, template arrays, decoded model
graph or image outputs are distributed by these tests.

## Remaining full-pipeline boundaries

The missing production integration is concrete: obtain the source frame with
verified range/primaries/orientation, run the matching face/attribute/skin
engines, map their landmarks/masks into that frame, reproduce native crop/warp
and texture sampling, run every active makeup/geometry/LUT stage with the actual
uniform values, define an HDR-safe appearance transform, and connect the
resulting HDR pixels to final encoding and regenerated gainmap. These wrappers
do not claim any of those steps is complete.

Further static work can establish colour-conversion channel selection, crop
warp flags/borders, texture upload orientation and node-specific transform
contracts. Device evidence is still needed to establish which live frame and
style settings actually traverse those routes and to compare native outputs.
For a useful device comparison, process the **same source image** with each
style and retain the original, output, exact intensity/settings, rotation and
mirror state. Separate camera exposures cannot establish numerical parity.
For exact internal parity, instrument the native boundary to export the face
crop, 106 landmarks/affine, model input/output tensor and mask from one capture;
the existing model-file exporter does not provide those tensors.
