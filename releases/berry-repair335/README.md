# Berry Browser BFCache描画復帰補正 v1.4.3

Hiro Morphe Patches v1.0.335に収録するBerry Browser用パッチです。
**前版の読み込み停止は改善したという実機報告を受け、残る表示崩れに対して描画復帰処理を追加します。実機で表示崩れの解消を確認した版ではありません。**

## 修正内容

前版は読み込み完了後に再描画を依頼しますが、その時点で画面から外れていたり非表示だったりした場合、再表示に追従する専用処理がありませんでした。
この版では、読み込み完了の状態と描画待ちを分離します。画面への接続・表示・寸法を確認してから描画準備通知を待ち、再描画を依頼します。
レイアウトの不整合が確認できた場合に限り、再レイアウトを要求します。小さな子Viewを親の大きさへ無条件に拡大する変更ではありません。

描画待ちには上限があり、新しいページ移動が始まったら古い処理を破棄します。元の復帰判定、ページと移動世代の照合、URL変更への追従、URL・タイトルと読み込み完了状態の同期を維持します。
描画待ちは1回の復帰につき最大3秒です。ネイティブの描画準備要求は未応答のものを重ねず、実際の通知が返るまで新しい要求を追加しません。要求済み通知そのものを取り消せないAndroid APIの制約を、待機要求を1件に制限することで扱います。
描画準備通知の到着・再描画要求・画面描画の観測と、見た目が正常になったことは別の事実です。ホスト試験で実機のピクセルの正しさを証明したとは扱いません。

画面寸法、倍率、スクロール位置、描画待ちの経過を上限付きの記録に残します。復帰後の小さな「描画記録」ボタンから確認し、必要なときだけコピーできます。URL・ページ本文・入力内容は記録せず、自動送信しません。
記録は最大4タブ・各64件です。古い記録から破棄し、WebView・Activityを記録のために強参照し続けません。ボタンは「アプリ再起動まで隠す」で非表示にできます。
表示崩れが残る場合は、再読み込みする前にその場で記録をコピーしてください。

## 今回までの実機報告

- BFCacheをOFFにすると正常。
- 保持ページ数を10から1へ減らしても改善しない。
- ユーザースクリプトを全部OFFにしても再現する。
- 崩れた後に再読み込みすると正常に戻る。
- v1.4.1／統合版1.0.332では改善しなかった。
- v1.4.2／統合版1.0.334で読み込み停止は改善したが、戻る操作を繰り返すと表示崩れが残る。

描画待ちの不足はコード上で確認した修正対象ですが、今回の実機症状の原因だったとは未証明です。メモリ不足、描画プロセス終了、GPU停止とも断定していません。

## 適用

1. Morphe ManagerでHiro Morphe Patchesを1.0.335へ更新します。Berry専用ソースを使う場合は1.4.3へ更新します。
2. 未改造のBerry Browserを入力に、元の4パッチと「バックフォワードキャッシュの復帰処理を補正」の計5パッチを適用します。
3. 統合版とBerry専用版は重複選択しません。以前と同じ署名キーで更新インストールします。
4. BFCacheとオートページャーは普段の設定のまま、新しいタブから問題が起きていた往復を確認します。

ソースの更新だけではインストール済みのアプリに変更は反映されません。アンインストールやデータ消去は不要です。

## 維持する動作

BFCacheの有効設定・最大ページ数、オートページャー、既存4改造、前版の読み込み完了補正を維持します。
強制リロード、履歴やキャッシュの削除、ユーザースクリプト全体の再実行は追加しません。
全バージョン表示と構造自動検出を引き継ぎ、必要な構造を確認できる入力だけに適用します。
統合版は最新1.0.334をベースにし、ULike v1.9.123を含む他アプリの定義と資産を保持します。

## 検証とソース

`payload/QA_apply335.json` は配布MPPのハッシュと適用試験、リリースの `QA_build335.json` は構築と保持検証、`payload/RUNTIME_BUILD_QA.json` は復帰・描画待ち・診断の試験を記録します。
ネイティブ完了処理のメタデータ保護と開始時引数の保護試験は `qa/native_audit/` に保存します。
保存済み未改造3.83.74と、クラス・メンバー名を変更した検証入力を使用します。実際のBerry 3.84.12のAPK、Android実機の表示・症状解消は未検証です。

`src/` はパッチ定義、`runtime/` は補正本体と試験、`build/` はMPP構築・保持検証、`qa/` は適用検証、`audits/` は開始処理・ページ識別情報の監査記録、`publication/` は公開処理です。
元APK、署名キー、閲覧データは公開しません。
固定した統合版1.0.334をベースにランタイムとMPPを2回構築し、同じバイト列になることと検証済みハッシュを確認します。
既存Siteへ公開した後、GitHubリリースとManagerのmain/dev更新情報を反映します。他アプリの内容・履歴を保持します。
