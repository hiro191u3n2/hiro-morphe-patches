# ULike v1.9.85 — GPU認定の引き継ぎと検証コピー所有権の修正

公開済みULike v1.9.84／Hiro Morphe Patches v1.0.217を固定基準として、認定後の採用経路、検証コピーの所有権、診断表示を修正します。新規配布はULike v1.9.85／総合版v1.0.218です。

## 修正範囲

1. Strongの比較基準が途中で不一致になった場合、失効した候補を参照し続けず、有効な基準を選び直します。GPU基準が残っていない場合は既存の実並列CPU比較へ進み、必要な全出力一致と速度条件を満たした候補だけを認定します。任意のCPU/GPU混在比較の後にも採用候補を再確認し、候補が失効していれば終了結果に反映します。
2. 次の撮影が始まったとき、古い撮影でコピーをまだ開始していない仮予約が新しい撮影のコピー枠を塞ぐ条件を修正します。開始済みのコピーの排他と実メモリの保持を守り、古い所有者の終了が新しい所有者の枠を解放しないことを確認します。1枚につき全体画像コピー1回、検証保持96MiB、処理順の公平性を維持します。延期理由は判定時の値で記録します。
3. 候補の確認一巡、認定への書込み回数、検証終了時の採用候補の成立を区別します。速度比較は対象の検証区間と基準を表示し、写真全体の処理時間と区別します。診断は小さな数値だけを保持し、保存済みの写真の処理時間・GPU件数や、採否・取消の動作を変えません。

## 保持と検証

画素の計算・NR・美肌・シャープ・保護処理・解像度・保存形式・カメラ/プレビュー/保存フックを保持。全12 nativeペイロード、GPU program 0〜50、JNI、画質認定のキーと不一致記録は公開.84と同一です。独立した2回の全出力一致と速度条件、GPU枠の待機上限、実際の転送予算を維持します。新しいnativeバイナリは作りません。

production1985.jsonとdiagnostic_methods1985.jsonで今回の本体クラスと既存メソッドの修正を宣言し、対象外のバイトコードを比較します。公開.84の全2087ソースはtests1985/source-scope84.jsonに固定し、旧版の試験を残して新しい仕様の正負の回帰を追加します。qa_contract1985.jsonは実行したホスト検証結果と必須要件を対応させ、認定・予算・取消・所有権・画素比較のゲートを維持します。

固定JDK21.0.8+9、Morphe1.16.0、Android/D8、NDKr27cを使用。declare1985.py → build1985.py → validate1985.py → finalize1985.py → publication/publish1985.pyで再構築・公開します。原本APKSへの適用・完成APKの静的検査を行い、そのMPPとCIの再構築MPPを完全一致させます。原本適用の実行場所と実機未検証を明記し、過去の検証件数を今回実行した件数へ加算しません。
