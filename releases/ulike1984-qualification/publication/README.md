# ULike v1.9.84 — GPU検証の保持予約・認定進捗の修正

公開済みULike v1.9.83／Hiro Morphe Patches v1.0.216を固定基準として、承認済みの3点を修正します。新規配布はULike v1.9.84／総合版v1.0.217です。

## 修正範囲

1. 検証画像をコピーする前に、キューの枠と保持メモリをまとめて予約します。StrongとGPU連結の検証を優先し、実際に受け入れられる場合に限り、待機中の補助検証を取り消して枠を空けます。同一の変更されないStrongモデルを使う検証は、各検証の画像コピー量とモデル一つ分の保持量を合算し、最後の所有者が終了するまでモデルを保持します。コピー中の取消を含め、検証保持96MiBの上限と解放の責任を管理します。
2. CPU比較の速度条件による待機を、独立した候補の画質検証から切り離します。一時的な利用・転送失敗、速度条件の不成立、画質不一致の扱いを区別し、完了済みの候補認定を次の検証で再利用します。後続の候補をすべて調べ終える前でも、完了した候補の残る速度比較と採用判定を進められるようにします。同じ撮影条件での認定、撮影再開時の取消、保存済みの不一致記録の扱いは維持します。
3. 検証の予約・実行・途中進捗と、完了・取消・メモリ不足・利用/転送失敗・速度未達・画質不一致などの終了理由を、画素データを含まない小さな履歴に記録します。認定成立は実際に認定結果が登録された場合に記録します。保存時の写真記録を保ったまま現在の検証状態を併記し、診断が採否を変更しないことを確認します。

## 保持と検証

画素の計算・NR・美肌・シャープ・保護処理・解像度・保存形式・カメラ/プレビュー/保存フックを保持。全12 nativeペイロード、GPU program 0〜50、JNI、画質認定のキーと不一致記録は公開.83と同一です。独立した2回の全出力一致と速度条件、GPU枠の待機上限、実際の転送予算を維持します。新しいnativeバイナリは作りません。

production1984.jsonとdiagnostic_methods1984.jsonで今回の本体クラスと既存メソッドの修正を宣言し、対象外のバイトコードを比較します。公開.83の全2058ソースはtests1984/source-scope83.jsonに固定し、旧版の試験を残して新しい仕様の正負の回帰を追加します。qa_contract1984.jsonは実行したホスト検証結果と必須要件を対応させ、認定・予算・取消・所有権・画素比較のゲートを維持します。

固定JDK21.0.8+9、Morphe1.16.0、Android/D8、NDKr27cを使用。declare1984.py → build1984.py → validate1984.py → finalize1984.py → publication/publish1984.pyで再構築・公開します。原本APKSへの適用・完成APKの静的検査を行い、そのMPPとCIの再構築MPPを完全一致させます。原本適用の実行場所と実機未検証を明記し、過去の検証件数を今回実行した件数へ加算しません。
