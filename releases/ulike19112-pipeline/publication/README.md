# ULike v1.9.112 / Hiro Morphe Patches v1.0.263

公開済み単体v1.9.111と総合版v1.0.262を固定ハッシュで取得する。他アプリの変更はバイト単位で保持する。

## 変更範囲

GPU保持画像を考慮したStrongの作業計画を見直す。連結時に並列数や区間行数を下げる前に、未使用CPU作業領域の整理と現在の使用可能容量・CPU空き枠の再取得を行う。容量上限と実行中領域の所有権を維持する。

保存後の強ノイズ候補検証の入力準備・領域確保・画素比較の区切りに取消確認を追加する。CPU基準の既存の取消確認と画素演算を維持する。取消や未完了を合格としない。

連結補正に128行の候補を追加する。選択した64行／128行を認定キーで区別し、比較・速度試行と認定後の計画の対応、容量上限、全画素一致2回と速度の採用条件を検証する。画素演算、Strongの厳密補間、入力・出力解像度、画質設定を維持する。

v1.9.111の工程別計測、2試行の比較表示、過去履歴と今回結果の区別を維持する。診断記録だけで認定を復元しない。

## 再構築と検証

Temurin21.0.8+9、Android NDK r27c、Morphe Desktop1.16.0、Android35/D8の固定ハッシュ、Python3.12系とNumPy2.3.5を使用する。

1. `src/declare19101.py`で本番ヘルパー、全ソース、公開スクリプトを固定する。
2. `src/build19101.py`で単体・総合MPPを構築する。完全DEX、既存ABI、他アプリ、ヘルパー参照を確認する。GPU nativeのアルゴリズムとシェーダーはv1.9.111のまま維持する。保守的なJava経路識別の変更で更新される埋込指紋だけを公開版へ戻す同一NDK再構築により、完全なv1.9.111 ELFとの一致を確認する。既存のv1.9.107→1.9.106領域補間逆変換の証拠も継続する。NRなど他11個のnative資産はv1.9.111と同一バイトを継承する。
   v1.9.111から継承した工程計測ヘルパーは診断専用の除外1件として明示する。この1行だけを逆変換して旧依存manifestの全バイト一致を確認し、数値処理・nativeの分類と指紋生成規則を維持する。
3. `src/host_audit19101.py`で既存の全試験群と今回追加した回帰試験を現在のソースに対して新たに実行する。固定入力の画素比較、実JNI/GLES、認定条件、取消・所有権、同じ上限での再判定、診断保存・復元を確認する。
4. `src/apply_original19101.py`で私有の未改造ULike5.6.2(740)APKSへ完成MPPを新たに適用し、FULL DEXとリソース再構築、arm64、元native保持、適用後メソッドを確認する。前版MPPの適用証拠は再利用しない。
5. `src/finalize19101.py`と`src/validate19101.py`で今回の実行証拠を配布MPPのSHA-256へ結び付ける。
6. `publication/publish19101.py --local-only`、`--preflight-only`の後に公開する。既存互換のためスクリプト名とschema名に19101が残るが、版値は1.9.112/1.0.263で照合する。

v1.9.112のAndroid実機での速度短縮は未確認。ホスト一致やAPK適用成功を実機での速度短縮・保存2,000ms以下達成の証拠にしない。

## 公開

検証済みdraft資産を公開し、固定commitの配布ファイルを再取得して一致確認後、main/devの両HEADを照合して直接子commitをatomic pushする。他の変更を保持する。既存release/tag/配布branchを上書きしない。
原本APKS、生成APK、個人写真・診断ログ、ツールチェーンは公開しない。ソース・テスト・匿名化した構造証拠のみ公開する。
