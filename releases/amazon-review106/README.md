# Amazon 商品検索の評価件数順 v1.0.6

対象は添付された Amazon ショッピング 32.19.0.100（versionCode 1243250306、Amazon v1.23.1 適用済み）です。
単独版は `Amazon_Review_Count_v1.0.6.mpp`、統合版は `Hiro_Morphe_Patches_v1.0.354.mpp` です。

v1.0.5で表示が変わらないという報告を受け、配布MPPのスクリプトが適用後APKへ組み込まれ、追加呼出しが入ることを再確認しました。これらの一致は確認できましたが、実機で処理がどこまで起動したかは未確認です。v1.0.6では起動対象のURL条件を見直し、Java側とWebView側の到達状況を区別する表示・端末内診断を加えます。実機の原因を特定したものでも、改善を確認したものでもありません。

約100商品を目安に先読みし、評価件数を判定できた主一覧の商品を一括で並べて順序を固定する方式を継続します。未判定・追加・件数変更の商品は待機させ、手動の「追加分を含めて並べ直す」で取得済み商品を再整理します。

## 起動と診断

Java側のスクリプト注入を検索・ホームのパス名で制限する処理を外し、信頼するAmazonのHTTPSページで起動を試みます。並べ替え自体は検索画面として確認できる範囲に限定します。アプリ側から検索の通知がある場合は、`#search` がなくても検索結果の標準的な枠と商品を確認して開始できるようにします。

Java側へ到達すると「評価件数順 v1.0.6 読込」をアプリのプロセスごとに1回表示します。WebViewの実行結果をコールバックで受け取り、実行結果を受け取れない場合のタイムアウトと、失敗段階を知らせる回数制限付きの通知を設けます。版番号の通知が出たことだけでは、検索一覧の認識や並べ替えの成功を意味しません。 受領確認の期限は5秒で、無応答を示す `E_ACK` はJavaScriptの例外が起きた証拠ではありません。失敗通知は同じコードを繰り返さず、プロセス内で最大3種類です。ホームや商品・カート画面が正しく対象外として応答した場合は、失敗とは扱いません。

端末内の診断は、固定の版番号・処理段階・上限100の一覧枠数/商品数/件数判定済み数・状態や上限到達の真偽値・定義済みのエラー種別に限定します。URL、検索語、ASIN、商品名、CSSクラス、例外の詳細メッセージは含めません。メモリー内だけで扱い、保存や外部送信は行いません。アプリ側の検索通知があるものの一覧構造を認識できない場合も、無表示で終わらず待機状態を案内します。

## 継続する認識と復帰

- URLがホームのままでも、表示中の検索枠と商品一覧を確認できる場合に処理を開始します。非表示の古い検索枠や、ページ内の同名変数で開始処理が妨げられる経路を修正しました。
- 有効なASINを持つ商品枠や、ASINのない外枠の内側の商品を取りこぼす経路を修正しました。商品1件の見出しを別区画と誤認しにくくし、商品に結び付く評価表示と確認できる単純な件数表記も扱います。認識できない商品が混じる場合は成功扱いせず、その旨を表示します。
- 操作中の初期待機、先読み・件数確認の進行状況、失敗時の表示を画面下部へ固定します。検索枠の外へ表示を置くことで、検索枠の表示状態の影響を受ける経路を修正しました。
- 件数を確認できず停止した後、商品識別子または件数に変化があり、判定可能な商品が現れた場合は、最大4秒の確認を経て再処理します。この復帰では自動先読みや再読み込みを行いません。
- 使用できる表示位置の情報が揃い、位置から見た件数順と並べた順序の矛盾を検出した場合は、「表示位置と件数順が一致しないため、そのまま表示」と案内します。これは全レイアウトを検証できる保証ではありません。

新しい検索を識別する通知がない場合の補完は、先頭位置で古い一覧枠が丸ごと置き換わり、新旧の商品が重ならない場合などに限定します。URLやアプリ側の通知で新検索を識別できず、同じ一覧枠が再利用される場合などは、新検索として確実に識別できません。

## 商品の確定と待機

通常の同じ表示形式の商品は、装飾クラスや内側の枠の違いだけで分割しないようにまとめます。件数の取得では画面に表示される値を優先します。主一覧へまとめられない別の表示形式、独立したスクロール領域、通常とは別の見出し付き区画は「対象外」として一時的に隠し、その件数を表示します。

先読み終了後、件数の表示を最大4秒（変化がない状態を800ミリ秒）待ち、判定できた主一覧の商品だけを並べ替えて固定します。件数未判定の商品、固定後に現れた商品、表示件数が変わった商品は待機対象として一時的に隠し、待機数を表示します。未整列の商品を固定した一覧の末尾へ自動で混ぜません。

「追加分を含めて並べ直す」を押すと、取得済みの待機商品を戻して件数を確認し、まとめて並べ直します。この操作では追加の自動先読みを行いません。件数を判定できる商品が1件もない場合は、商品を空にせず、一時的に隠した商品を戻して表示します。「評価件数を確認できないため、そのまま表示」と再試行を案内します。処理対象が上限を超えた場合も隠した商品を戻し、「商品が多いため並び順を確認できません」と表示します。いずれも評価件数順に整理できたとは案内しません。固定後に自動で先頭へスクロールさせる処理は行いません。URLやアプリ側の通知などから新しい検索と識別できた場合は、固定した対象を作り直します。

対象は取得済み・件数判定済みの商品です。評価件数には星だけの評価も含み、文章付きレビューの件数とは一致しません。未取得・待機中の商品も含めた全検索結果の順位ではありません。

## 先読み

先読みはAmazonアプリの既存の追加読み込みを使い、検索結果リストの範囲内を自動で下へ進めます。同じASINの重複分を除いた約100商品が目安で、1回の読み込みで100件を超える場合があります。ページ全体のフッターへ移動する方式ではありません。

自動スクロールの上限は20秒・30回です。末尾で一定回数商品が増えない場合も打ち切ります。最初の商品が20秒間現れない場合は自動スクロールと定期確認を止めて検索結果の更新を待ち、後から現れた初回群を追加先読みなしで扱います。自動先読みと件数の判定待ちの上限を合わせると約24秒です。画面操作中は処理を待機します。100件の取得は保証しません。

画面へのタッチ、ポインター、ホイール、キー操作やページの非表示化で自動先読みを止めます。途中位置や再利用された検索画面、「戻る・進む」で復元された画面では自動で先へスクロールしません。通常の先頭からの検索では、先読み終了時に元の先頭へ戻し、その後の固定一覧を閲覧します。

v1.0.5と同じ6箇所のネイティブフックを保持します。読み込み・ページ完了に加え、`MShopWebViewClient.doUpdateVisitedHistory` と `InteractionWebFragment.onFragmentPostShown` を検証付きでフックします。元の広告非表示や価格履歴を含む既存処理を保持し、6メソッドへ合計8命令を追加します。 Java側の注入では検索・ホームのパスによる制限を設けず、信頼するAmazonのHTTPS URLかを検証します。

## 適用

元の添付APKを選び、「商品検索を評価件数の多い順に表示」だけを適用してください。v1.0.0〜v1.0.5を適用したAPKへの重ね掛けは受け付けません。単独版と統合版のどちらか一方を使用し、以前と同じ署名で作成したアプリを上書きインストールします。ソース更新だけではインストール済みアプリは変わりません。

## 再現ビルド

JDK 21.0.13、`publication/baseline.json` の固定された統合353、`src/build.py` のSHA-256と一致する5ツールを使用します。`morphe.jar` は旧JavaパッチAPIのコンパイル専用で、適用・検証には公式Patcher 2.2.0を含む `morphe-2.2.jar` を使います。 `json.jar` はホスト上でAndroid標準JSON処理の受領試験を行うためだけに使用し、配布MPPやAndroidランタイムには組み込みません。

```sh
npm ci --ignore-scripts --no-audit --no-fund --prefix src/runtime-tests
python3 src/build.py --base baseline353.mpp --tools tools --work build-a --dist dist-a --apk supplied.apk
python3 src/build.py --base baseline353.mpp --tools tools --work build-b --dist dist-b
```

各ビルドは新しい作業ディレクトリと空の出力先を指定します。JDKを別途指定する場合は `--java-home /path/to/jdk-21.0.13` を追加します。配布MPPの全バイトが2回のビルドで一致することを確認します。

`--apk` を指定したビルドは、単独版と統合版をPatcher 2.2.0の `STRIP_FAST` で実際に適用します。生成したDEXのクラス一覧と変更箇所、既存メソッド、ランタイム、APKの全非DEX資源を照合します。Javaの起動条件、URL、ガード、二重適用拒否、DOMの件数取得・待機・手動統合をホストテストで確認します。Javaから生成したスクリプトを試験用WebView/JavaScript環境で実行し、結果がJavaの受領処理まで往復する経路、診断項目とタイムアウトも確認します。公開前のローカル検証は、QAの `bridge_roundtrip_tests` がPASSであることも必須条件にします。

位置やスクロールはテスト用の矩形・値による合成ジオメトリで検証します。実ブラウザーでの描画試験やAndroid実機での操作試験は行っていません。今回の端末での原因の断定と改善確認は未実施です。

統合353から置換するのは `app/hiro/amazonreviews/patches/` と `extensions/amazon_review_sort.mpe` だけです。他パッチのクラスと資源は保持します。APK適用結果は `QA_Amazon_Review_Count_v1.0.6.json` に記録します。元APK、実機の検索内容、アカウント情報を公開物に含めません。
