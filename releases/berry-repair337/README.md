# Berry Browser スクロール後診断 v1.4.4

Hiro Morphe Patches v1.0.337に収録するBerry Browser用パッチです。
戻った直後の記録だけでは捉えられなかった、スクロール後の表示崩れを調べるために数値診断を追加します。実機で表示崩れの解消を確認した版ではありません。

## 追加する診断

復帰後、最初のスクロール後、スクロールが落ち着いた時点と「描画記録」を開いた時点に、同じ文書のviewport・スクロール位置・倍率を取得します。
画像の読み込み完了、正の画像寸法、画面内への配置を件数で記録します。記録の取得待ち時間と、その間に位置が変わったかも残します。
端末の表示密度と使用中WebViewの提供元・バージョンを追加します。WebViewの倍率には表示密度も含まれるため、倍率値だけをズーム率とみなさないでください。

URL・ページタイトル・本文・フォーム入力・画像URLは記録しません。取得するページ情報は固定の数値項目に限定し、画像の画素や内容は読み取りません。
ページをまたぐ応答や不正な数値は採用せず、観測時間・試行数・画像確認数・保存件数・未応答要求に上限を設けます。記録は自動送信せず、コピーは利用者がボタンを押した場合だけです。

自動観測は復帰後45秒以内で、復帰直後・最初にスクロール位置が変わった時点・スクロール停止後の最大3回です。停止は200msの静止で判定します。画像は文書内の先頭128件までで、画面内の全画像を確認した保証はありません。
最大4タブに、従来の描画記録を各64件、スクロール診断を各8件保持します。未応答の診断要求はWebViewごとに1件です。800msで記録上の待機を終えても、実際の応答が返るまでは次の診断要求を増やしません。
自動観測が終わった後も、同じ復帰ページで記録を開くと取得を試みます。JS_BUSYやJS_TIMEOUTと出た場合、最新のページ内数値は取得できていません。画像の配置を読む処理自体がブラウザのレイアウト計算に影響する可能性はあります。

元の読み込み完了補正とv1.4.3の描画復帰処理は保持します。今回は追加の再描画、レイアウト変更、リロード、倍率変更を行いません。
記録された画像件数や描画通知が正常でも、画面のピクセルが正常である証明にはなりません。ページの画像表示とWebViewの描画・合成のどちらが原因かは未確定です。

## 適用と記録の取り方

1. Morphe ManagerでHiro Morphe Patchesを1.0.337へ更新します。Berry専用ソースの場合は1.4.4へ更新します。
2. 未改造のBerry Browserに、既存4パッチと「バックフォワードキャッシュの復帰処理を補正」の計5パッチを適用します。
3. 統合版と専用版を重複選択せず、以前と同じ署名キーで更新インストールします。ソースの更新だけではアプリは変わりません。
4. 新しいタブで普段のページを開き、戻る操作の後にスクロールします。
5. 表示が崩れたら、再読み込みする前に「描画記録」を開きます。約1秒待ち、採取中の表示が消えてからコピーしてください。

BFCacheとオートページャーは普段の設定のまま使えます。アンインストールやデータ消去は不要です。「アプリ再起動まで隠す」で記録ボタンを非表示にできます。

## 保持と検証範囲

BFCacheの有効設定・最大ページ数、オートページャー、既存4改造を維持します。統合版は公開済み1.0.336をベースとし、ULike v1.9.124を含む他アプリを保持します。
保存済み未改造3.83.74とクラス・メンバー名を変更した入力で適用を検証します。実際のBerry 3.84.12のAPK、新診断のAndroid実機動作、実機の表示崩れ解消は未検証です。

`payload/QA_apply337.json` はMPP適用とフック検査、リリースの `QA_build337.json` は構築と保持検証、`payload/RUNTIME_BUILD_QA.json` は通知順序・描画待ち・数値診断のホスト試験です。
`payload/QA_runtime_delta337.json` は診断追加に伴う実行コード差分、`payload/provider_preservation337.json` は既存パッチ定義の保持を検査します。
`payload/SDK_compile337.json` は実SDKを使ったソースのコンパイル結果です。コンパイル成功をAndroid実行や画面正常性の確認とは扱いません。
`qa/native_audit/` はネイティブ完了処理と開始時引数の保護試験、`audits/presentation-audit/` は報告の読み取り範囲と実装レビューです。元のAPK、署名キー、利用者のスクリーンショットは公開しません。

`src/` はパッチ定義、`runtime/` は実行本体と試験、`build/` はMPP構築・保持検証、`qa/` は適用検証、`publication/` は公開処理です。
固定した統合版1.0.336を使ってランタイムとMPPを2回構築し、検証済みのバイト列と一致することを確認します。既存Siteへの公開後、GitHubリリースとManagerのmain/dev更新情報を反映します。
