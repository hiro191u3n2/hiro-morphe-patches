The production shader library `native1960/soft64_1965.glsl` represents IEEE
binary64 as `uvec2(low32, high32)`. It uses GLES 3.1 integer arithmetic only;
native FP64 and native 64-bit integers are not required. Every arithmetic
operation rounds independently to nearest, ties to even. Finite subnormals,
signed zeros, infinities and NaNs are retained. Min/max propagate NaNs and order
negative zero before positive zero. Input/output pixel formats still use the
existing production interfaces.

`soft64_port1965.py` deterministically adapts the included Mesa source snapshot
(SHA256 `2fa2575aca36750f40faf91d043babf65f5f3b6c34db596822b05a16f725e149`).
The port replaces public uint64 values with uint32 pairs; fixes upstream
subnormal increment signedness and halfway tie rounding; masks variable shift
distances to remove undefined GLES eager-expression shifts; and preserves
signed zeros in truncation/floor. Exact restoring division is in the explicit
API. The included source and generated library retain the Berkeley SoftFloat
3e BSD 3-clause notice; binary distributions must reproduce that notice in
accompanying materials.

Validation command, run from this release's `src` directory:

```sh
python tests1965/soft64_port1965.py
python tests1965/soft64_arithmetic1965.py --work /tmp/soft64-1965 --samples 100000
```

The test expands the library marker exactly as the production builder does
and dispatches the unmodified `#version 310 es` shader on surfaceless EGL/GLES.
It compares readback with independent host binary64, bit for bit (NaN payloads
are not required to match). It exercises add/subtract/multiply/divide/sqrt,
floor/truncate, conversions, comparisons, min/max, abs/negation and finite/zero
classification, with random finite bits and boundary/tie/subnormal values.
It also dispatches the production 16-word arithmetic admission probe and GPU
alpha admission probe. A CPU reference exists only in the test harness.

The October 9, 2026 run passed 1,802,896 arithmetic cases with zero differences
on OpenGL ES 3.2 Mesa 25.2.8 (llvmpipe); no shader dialect changes or FP64
extensions were used. Physical Android hardware, driver performance and
camera lifecycle are not established by this host arithmetic test.
