# Amazon 商品検索の評価件数順 v1.0.4

対象は添付された Amazon ショッピング 32.19.0.100（versionCode 1243250306、Amazon v1.23.1 適用済み）です。
単独版は `Amazon_Review_Count_v1.0.4.mpp`、統合版は `Hiro_Morphe_Patches_v1.0.352.mpp` です。

約100商品を目安に先読みし、評価件数を判定できた商品を一括で並べて順序を固定します。装飾用クラスや内側の枠による通常一覧の分断、非表示の古い件数を優先する取得、件数の表示前の順位固定、固定後に未整列の商品を末尾へ加える処理を修正します。これらはホスト側で再現した問題で、今回の端末で同じ経路が発生したことを確定したものではありません。

## 商品の確定と待機

通常の同じ表示形式の商品は、装飾クラスや内側の枠の違いだけで分割しないようにまとめます。件数の取得では画面に表示される値を優先します。主一覧へまとめられない別の表示形式、独立したスクロール領域、通常とは別の見出し付き区画は「対象外」として一時的に隠し、その件数を表示します。

先読み終了後、件数の表示を最大4秒（変化がない状態を800ミリ秒）待ち、判定できた主一覧の商品だけを並べ替えて固定します。件数未判定の商品、固定後に現れた商品、表示件数が変わった商品は待機対象として一時的に隠し、待機数を表示します。未整列の商品を固定した一覧の末尾へ自動で混ぜません。

「追加分を含めて並べ直す」を押すと、取得済みの待機商品を戻して件数を確認し、まとめて並べ直します。この操作では追加の自動先読みを行いません。件数を判定できる商品が1件もない場合は、商品を空にせず、一時的に隠した商品を戻して表示します。「評価件数を確認できないため、そのまま表示」と再試行を案内します。処理対象が上限を超えた場合も隠した商品を戻し、「商品が多いため並び順を確認できません」と表示します。いずれも評価件数順に整理できたとは案内しません。固定後に自動で先頭へスクロールさせる処理は行いません。検索条件が変わると新しい検索として扱います。

対象は取得済み・件数判定済みの商品です。評価件数には星だけの評価も含み、文章付きレビューの件数とは一致しません。未取得・待機中の商品も含めた全検索結果の順位ではありません。

## 先読み

先読みはAmazonアプリの既存の追加読み込みを使い、検索結果リストの範囲内を自動で下へ進めます。同じASINの重複分を除いた約100商品が目安で、1回の読み込みで100件を超える場合があります。ページ全体のフッターへ移動する方式ではありません。

自動スクロールの上限は20秒・30回です。末尾で一定回数商品が増えない場合も打ち切ります。最初の商品が20秒間現れない場合は自動スクロールと定期確認を止めて検索結果の更新を待ち、後から現れた初回群を追加先読みなしで扱います。件数の判定待ちを含む初回の処理時間は最大約24秒です。100件の取得は保証しません。

画面へのタッチ、ポインター、ホイール、キー操作やページの非表示化で自動先読みを止めます。途中位置や再利用された検索画面、「戻る・進む」で復元された画面では自動で先へスクロールしません。通常の先頭からの検索では、先読み終了時に元の先頭へ戻し、その後の固定一覧を閲覧します。

v1.0.3と同じ6箇所のネイティブフックを保持します。読み込み・ページ完了に加え、`MShopWebViewClient.doUpdateVisitedHistory` と `InteractionWebFragment.onFragmentPostShown` を検証付きでフックします。元の広告非表示や価格履歴を含む既存処理を保持し、6メソッドへ合計8命令を追加します。

## 適用

元の添付APKを選び、「商品検索を評価件数の多い順に表示」だけを適用してください。v1.0.0〜v1.0.3を適用したAPKへの重ね掛けは受け付けません。単独版と統合版のどちらか一方を使用し、以前と同じ署名で作成したアプリを上書きインストールします。ソース更新だけではインストール済みアプリは変わりません。

## 再現ビルド

JDK 21.0.13、`publication/baseline.json` の固定された統合351、`src/build.py` のSHA-256と一致する4ツールを使用します。`morphe.jar` は旧JavaパッチAPIのコンパイル専用で、適用・検証には公式Patcher 2.2.0を含む `morphe-2.2.jar` を使います。

```sh
npm ci --ignore-scripts --no-audit --no-fund --prefix src/runtime-tests
python3 src/build.py --base baseline351.mpp --tools tools --work build-a --dist dist-a --apk supplied.apk
python3 src/build.py --base baseline351.mpp --tools tools --work build-b --dist dist-b
```

各ビルドは新しい作業ディレクトリと空の出力先を指定します。JDKを別途指定する場合は `--java-home /path/to/jdk-21.0.13` を追加します。配布MPPの全バイトが2回のビルドで一致することを確認します。

`--apk` を指定したビルドは、単独版と統合版をPatcher 2.2.0の `STRIP_FAST` で実際に適用します。生成したDEXのクラス一覧と変更箇所、既存メソッド、ランタイム、APKの全非DEX資源を照合します。Javaの起動条件、URL、ガード、二重適用拒否、DOMの旧版問題の再現・件数取得・待機・手動統合をホストテストで確認します。

位置やスクロールはテスト用の矩形・値による合成ジオメトリで検証します。実ブラウザーでの描画試験やAndroid実機での操作試験は行っていません。今回の端末での原因の断定と改善確認は未実施です。

統合351から置換するのは `app/hiro/amazonreviews/patches/` と `extensions/amazon_review_sort.mpe` だけです。他パッチのクラスと資源は保持します。APK適用結果は `QA_Amazon_Review_Count_v1.0.4.json` に記録します。元APK、実機の検索内容、アカウント情報を公開物に含めません。
