# Hiro TikTok 47.4.3 対応 v4.1.0

対象はグローバル版 TikTok **47.4.3 / `com.zhiliaoapp.musically`** です。前の v4.0.0 が対象にしていた 47.5.3 の対応も保持します。47.4.3 の実 APK にある戻る操作、ホーム選択、シークバー、プレビュー、フィード表示の処理を調べ、版ごとに実装を分けました。

## 配布ファイル

- `TikTok_47.4.3_Hiro_v4.1.0.mpp`：今回の TikTok 向け8項目をまとめた追加パッチ。
- `Hiro_Morphe_Patches_v1.0.281.mpp`：既存の Hiro 統合版を更新したファイル。TikTok 以外のパッチも含みます。

同じパッチが重複するため、通常はどちらか一方を読み込んでください。両方とも 47.4.3 と 47.5.3 に対応します。日本語設定を使う場合は、別途 [icysymmetra の TikTok パッチ v0.9.0-dev.1](https://github.com/icysymmetra/tiktok-patches-for-morphe/releases/tag/v0.9.0-dev.1) の `Settings` が必要です。

## 適用方法

1. Hiro ソースを総合版 **1.0.281** に更新するか、上記の単体 MPP を読み込みます。
2. パッチ未適用の **TikTok 47.4.3 / `com.zhiliaoapp.musically`** の完全な APK を選びます。検証した versionCode は `2024704030` です。
3. Hiro の必要な項目を選びます。通信保護などの名前が `（TikTok 47.4.3・47.5.3）` になっていることを確認してください。
4. 設定の日本語化も使う場合は、icysymmetra の `0.9.0-dev.1` を有効にし、上流の **`Settings`** と Hiro の **`TikTok設定を日本語化`** を同時に選びます。端末またはアプリの言語を日本語にします。
5. 適用後、選択した全項目の成功を確認します。

47.4.3 では Hiro と上流 Settings の両方の対応バージョンが一致します。検証でも互換性判定の強制無視は使用していません。手動選択に必要な Manager の機能は使用中の版によって異なる場合があります。参考として、2.1.0-dev.2 のエキスパート モードと選択フィルターのソース確認記録を `src/validation/manager/manager-selection-audit.md` に残しています。

今回のネイティブ6項目は、47.x の別パッケージ `com.ss.android.ugc.trill` や他バージョンには対応済みとして表示しません。確認した実構造が一致しなければ、その機能の適用を停止します。

## 実 APK の検証

両原本の署名を Google apksig で API23〜37 に対して検証し、同じ署名証明書であることを確認しています。

| 原本 | versionCode | bytes | 元の DEX クラス数 |
| --- | ---: | ---: | ---: |
| 47.4.3 | 2024704030 | 474921201 | 475931 |
| 47.5.3 | 2024705030 | 476733983 | 480524 |

47.4.3 の SHA-256 は `af7cbe2b00d33ff1339730f6abb8ed7e387a83b27ff2b16748b8f41e6fc87e0b`、47.5.3 は `6670ca3f93bfea379658cad3c27f05d3a380b23a0d82569cce684b7453e8ff3e` です。署名証明書 SHA-256 は `9041803e91bcb814b4b4399fb5c85a91640b755e5e8ba76813814bf4cf2ab5ba` です。

次の2構成を各版で実行し、合計4ケースが適用・再構築・出力監査まで成功しました。

1. 単体 MPP：ネイティブ6項目＋OneBack の7パッチ。
2. 総合 MPP：Hiro 製8項目＋上流 Settings の9パッチ。

選択したパッチと成功したパッチが一致し、失敗0件で適用・再構築を含む全工程が成功することを要求します。出力 APK のネイティブ呼び出し、分岐、クラス・メンバーの保持、通信保護、設定の日本語化接続も監査します。47.5.3 でのみ、上流 Settings の版指定を CLI で上書きして既存対応の回帰検証を行いました。

| 検証した構成 | 47.4.3 | 47.5.3 |
| --- | --- | --- |
| 単体7パッチ | 適用・再構築・全出力監査 PASS | 適用・再構築・全出力監査 PASS |

MPP はローカル2回と GitHub Actions 2回で独立してビルドし、実 APK に適用した MPP とバイト単位で一致させます。OneBack は85 runtime class のうち TikTokHome だけを変更し、他84個を保持します。統合版の無関係なパッチ・リソース、日本語化、ULike の運用設定も保持します。元 APK と生成した APK は公開資産に含めません。

**Android 17 / Samsung SM-S948Q を含む実機の表示・操作・接続中の挙動は未確認です。** 動画プレビューには配信側の画像データが必要です。任意の128項目の選択内容全体を確認したという意味でもありません。

## 上流パッチの扱い

今回の変更対象は Hiro 製8項目です。上流の `0.9.0-dev.1` は 47.4.3 向けです。

### 47.4.3 での追加併用検証

上流136項目＋Hiro8項目の全144項目を明示的に選択し、修正版の単体MPPで **144項目適用・失敗0件・APK再構築成功** を確認しました。互換性の強制無視は使わず、既定のパッチオプションと Patcher 2.0.0、`-Xmx3g` を使用しています。3GBは、Manager 2.1.0 の通常の64bit内蔵実行環境の上限に合わせた条件です。メモリ設定の根拠は [publication/manager-memory/audit-summary.json](publication/manager-memory/audit-summary.json) にあります。

生成APK内の元のライブラリ593パスを検査し、上流が空にした18パスだけが空のまま残っていること、通信保護が変更した非空16ファイルのサイズとSHA-256が処理ログと一致することも確認しました。[publication/metra-all144/](publication/metra-all144/) に実行条件・未加工の結果・追加監査を保存しています。修正前の2GBメモリ不足と4GBでの通信保護失敗も、別の履歴として残しています。

この追加確認は適用・再構築と上記ライブラリ処理の検証です。全144項目の機能を実機で確認したという意味でも、選択内容が不明なユーザーの128項目構成を再現したという意味でもありません。必須の4ケースでは、Hiroの出力処理とSettings・日本語化を詳しく監査しています。
