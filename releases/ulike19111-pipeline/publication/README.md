# ULike v1.9.111 / Hiro Morphe Patches v1.0.262

公開済み単体v1.9.110と総合版v1.0.261を固定ハッシュで取得する。他アプリの変更はバイト単位で保持する。

## 変更範囲

保存後のGPU連結検証に有界な工程別計測を追加する。既存経路と連結候補について、試行・工程・完了状態を区別する。画質の全画素比較が完了した結果と速度による不採用を分け、途中進捗を完了結果として表示しない。永続診断は今回の結果と過去の履歴を区別する。

v1.9.110のStrong保持準備時の型別拒否、確認済み容量不足時の未使用CPU作業領域の整理と同じ予算での再判定、画像・セッション・実行中領域の所有権、撮影ごとの検証コピー優先交代を維持する。

CPU/GPU画素演算、Strongの厳密補間、入力・出力解像度、画質設定は変更しない。全画素一致2回と速度の採用条件を維持し、途中終了時は認定しない。診断記録だけで認定を復元しない。

## 再構築と検証

Temurin21.0.8+9、Android NDK r27c、Morphe Desktop1.16.0、Android35/D8の固定ハッシュ、Python3.12系とNumPy2.3.5を使用する。

1. `src/declare19101.py`で本番ヘルパー、全ソース、公開スクリプトを固定する。
2. `src/build19101.py`で単体・総合MPPを構築する。完全DEX、既存ABI、他アプリ、ヘルパー参照を確認する。GPU nativeのアルゴリズムとシェーダーはv1.9.110のまま維持する。保守的なJava経路識別の変更で更新される埋込指紋だけを公開版へ戻す同一NDK再構築により、完全なv1.9.110 ELFとの一致を確認する。既存のv1.9.107→1.9.106領域補間逆変換の証拠も継続する。NRなど他11個のnative資産はv1.9.110と同一バイトを継承する。
   新しい工程計測ヘルパーは診断専用の除外1件として明示する。この1行だけを逆変換して旧依存manifestの全バイト一致を確認し、数値処理・nativeの分類と指紋生成規則を維持する。
3. `src/host_audit19101.py`で既存の全試験群と今回追加した回帰試験を現在のソースに対して新たに実行する。固定入力の画素比較、実JNI/GLES、認定条件、取消・所有権、同じ上限での再判定、診断保存・復元を確認する。
4. `src/apply_original19101.py`で私有の未改造ULike5.6.2(740)APKSへ完成MPPを新たに適用し、FULL DEXとリソース再構築、arm64、元native保持、適用後メソッドを確認する。前版MPPの適用証拠は再利用しない。
5. `src/finalize19101.py`と`src/validate19101.py`で今回の実行証拠を配布MPPのSHA-256へ結び付ける。
6. `publication/publish19101.py --local-only`、`--preflight-only`の後に公開する。既存互換のためスクリプト名とschema名に19101が残るが、版値は1.9.111/1.0.262で照合する。

v1.9.111のAndroid実機での速度短縮は未確認。ホスト一致やAPK適用成功を実機での速度短縮・保存2,000ms以下達成の証拠にしない。

## 公開

検証済みdraft資産を公開し、固定commitの配布ファイルを再取得して一致確認後、main/devの両HEADを照合して直接子commitをatomic pushする。他の変更を保持する。既存release/tag/配布branchを上書きしない。
原本APKS、生成APK、個人写真・診断ログ、ツールチェーンは公開しない。ソース・テスト・匿名化した構造証拠のみ公開する。
