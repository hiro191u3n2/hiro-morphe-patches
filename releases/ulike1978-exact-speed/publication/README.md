# ULike v1.9.78 — 画質を維持する保存高速化

公開済み ULike v1.9.77 / 総合版 v1.0.210 の実配布ファイルを固定基準にします。新しい配布物は ULike v1.9.78 / 総合版 v1.0.211 です。

## 採用案1〜7

1. 実並列の完了時間で GPU・CPU の区間配分を認定します。
2. 未認定 Strong GPU の完全一致照合を保存後の idle queue に移します。
3. CPU が確定した保護情報を直接 GPU へ転送します。
4. 前段作業域とモデル解析中の同じ計算を再利用します。
5. 変更されないマスクの補正信頼度を共用し、帯の準備を並行化します。
6. GPU 連結の half 複製・比較メモリ寿命・前提認定順を改善し、等倍を専用の同値経路で扱います。
7. 2の累乗の除算だけを厳密に高速化した GPU program 45〜50 を追加します。

画質基準は .77 の保存前 ARGB、モデル／evidence の浮動小数点ビット列、保護整数です。解像度、画質設定、保存形式や圧縮を落とす変更はありません。CPU・GPU の実装変更をバイト不変と誤記せず、変更部分には実行した同値試験を要求します。未知コールバックの呼出し順、キャンセル、一括 commit、所有権とメモリ上限を保持します。

## 再現と検証

`src/declare1978.py` が全ソースと公開処理を固定し、`src/build1978.py` が .77/.210 から構築します。JDK 21.0.8+9、Android NDK r27c（27.2.12479018）と固定した Java ツールを使用します。`src/validate1978.py` は実行結果、ソース、DEX、native、配布物の指紋を照合します。`src/finalize1978.py` が公開用 QA・ソースアーカイブ・説明を作ります。

既存 GPU program 0〜44 を残し、2回の独立した全出力照合と候補ごとの速度条件を使用します。GPU・前段 NR の2 nativeライブラリを再構築し、残り10ペイロードは保持します。作業域の新 JNI は create / release / begin / end の4宣言だけです。カメラ・保存制御と他アプリの資源を DEX／バイト比較で保全します。

`publication/publish1978.py` は独立した公開 manifest と実ファイルを確認します。`--local-only` と `--preflight-only` は公開を書き換えません。公開時には GitHub Release と不変の MPP URL を検証してから、main と dev の両 Manager feed を現在 HEAD の直接の子へ atomic push します。既存履歴と他アプリを保持します。

今回の元 APKS 適用、Android 実機の撮影・画質・保存速度は未実施です。ホストの実 JNI／シェーダー検証と Android 実機の速度測定は区別します。区間群の速度認定を写真全体の保存時間や約1900msへの復帰の実証として扱いません。利用者の写真・診断ログ・元 APK・署名鍵を配布に含めません。
