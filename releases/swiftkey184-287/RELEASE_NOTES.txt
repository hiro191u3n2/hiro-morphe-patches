Microsoft SwiftKey Beta v1.8.4 / Hiro Morphe Patches v1.0.287

日本語QWERTYの「グライド入力（試験機能）」を修正します。
ローマ字のキーをなぞり、指を離した後に表示される読みを選ぶと、
SwiftKey本来の日本語変換へ渡します。その後は通常の候補から漢字などを選べます。
読みの候補は横にスクロールできます。×でその入力を取り消せます。

今回の変更
・同じ軌跡になる「ねこ／ねっこ」などや、途中のキーが一直線に並ぶ読みを、
  候補なしで捨てず、複数の候補として表示します。自動で読みを決め打ちしません。
・次のタッチによって前の認識結果を取り消す処理を改め、入力を順番に処理します。
  入力欄・カーソル・本文・配列が変わった場合には、古い入力先へ書き込みません。
・長押し時間の設定が短いだけで開始できなくなる条件を除きます。
  通常のタップ・実際の長押しメニュー・LINEの長押し改行との共存を維持します。
・固定された標準配列の幅や間隔ではなく、実際のキー位置を使います。
  日本語の標準・片手・PC・分割QWERTY配列を対象にし、指とスタイラスに対応します。
  文字段からの軽微なはみ出しで直ちに認識を破棄しないようにします。
・辞書の準備中の入力を待機させ、準備中・認識失敗などの状態を表示します。
・既存のグライド辞書を維持したまま、短い読みや一般的なあいさつを補います。
  辞書で見つからない場合にも、軌跡から作れる読みを補助候補として扱います。
  補助候補も本体のローマ字変換で検証し、選択された場合だけ入力します。
・シークレット入力では本体の学習抑止を維持します。「学習しない」指定の欄は、
  本体側で学習抑止が有効になったことを確認してから処理します。
  独自の入力履歴保存や通信は追加しません。パスワード欄などは引き続き対象外です。
・設定画面の説明を、新しい候補選択と対応配列に合わせます。設定の初期値はオフです。

既存の日本語辞書・ポケモン名・スラング・Samsung絵文字・キー交換・横画面・
LINE改行・カーソル移動や削除時のLatin保護を維持します。
総合版は公開済みv1.0.286を土台にし、ULikeなど他アプリ向けの内容を保持します。

検証と限界
修正版Javaのホスト回帰検査、DEX再構築後のクラス比較、対象版APIとの照合、
単体版と総合版のSwiftKey資産一致、既存資産のバイト比較を公開条件にします。
GitHub Actionsで同じソースから2回再ビルドし、ローカルの検証済みMPPとの
SHA-256一致を確認した後に、公開資産とmain/dev両方のManagerフィードを更新します。
対象APIの照合には保存済みの同版v2改造APKを使用します。
未改造APKへの今回のパッチ一括適用、Android/ART実行、Galaxy実機操作は未確認です。
ホスト試験は実機での認識率・候補欄の表示・操作感を保証するものではありません。
同じ軌跡から本来の読みを常に一意に復元することはできず、任意の新語や長文すべての
認識を保証しません。候補がない場合は通常のキー入力を利用できます。

適用方法
対象: Microsoft SwiftKey Beta 9.13.16.4（versionCode 1236271168）。
Morphe ManagerでHiroソースを総合v1.0.287へ更新するか、単体v1.8.4を読み込み、
元の未改造APK/APKSへ「日本語入力・予測変換を改善しSamsung絵文字に統一」を
再適用してください。既存と同じ署名鍵で上書きインストールします。
すでにグライド入力をオンにしている場合は、その設定を引き継ぎます。
ソースの更新だけではインストール済みSwiftKeyの動作は変わりません。
アプリのデータ削除やアンインストールは不要です。
